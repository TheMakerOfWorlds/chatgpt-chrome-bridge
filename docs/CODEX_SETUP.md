# ChatGPT Chrome Bridge setup guidance

These instructions apply when a user asks Codex to install or set up this bridge. For maintenance, preserve existing account and project preferences unless the user requests a change.

1. Read `docs/INSTALL.md`. Check macOS, Chrome, Node.js 20+, and the Codex CLI. Help install missing prerequisites using the user's normal package manager when authorized.
2. Use only the installer's own Chrome profile and ChatGPT account. Never copy login state or configuration from the maintainer or another machine. If multiple local profiles exist, ask which one to use. The Chrome profile name is not proof of the ChatGPT account signed in inside it; let the user choose/sign in to the intended ChatGPT account.
3. During first setup, explicitly ask: **“Where should new ChatGPT chats go: no project (ordinary chats), or a project in your ChatGPT account?”** Offer **No project (recommended default)** and **Choose a project**. If they choose a project, ask them to open that project in their own ChatGPT account and paste its URL. Do not infer a destination from this repository, the active Codex project, the maintainer's account, or the user's folder name. If the user already provided their choice in this conversation, use it without asking again. Wait for the choice before changing the preference; missing input is not a choice.
4. Run `sh install.sh --no-project` for no project, or `sh install.sh --project-url 'https://chatgpt.com/g/g-p-.../project'` with the supplied URL. Pass `--profile` when the user has selected a local Chrome profile. Use structured command arguments or proper shell quoting for user-supplied values. For a Codex-controlled shell, allocate a terminal if the installer needs interactive input. Do not claim the user can answer a terminal prompt that only Codex controls; relay necessary prompts through the conversation.
5. Let the user complete ChatGPT login/MFA themselves in the dedicated visible Chrome window when needed. They should quit that dedicated Chrome instance with Command-Q before login verification. Do not collect passwords or copy cookies manually. A noninteractive authentication failure needs the documented login flow, not repeated installation.
6. The installed maintenance command supports `project --no-project` or `project --project-url URL`; use it to finish the choice if installation completed earlier or the current Codex task has not loaded the plugin tools yet. Once loaded, `configure_chatgpt_bridge(project_url: "")` clears the project and a URL sets it. Read back the saved preference (maintenance `doctor` or bridge status) and report the user's selected destination. A valid URL alone does not prove account access to that project.
7. Explain that new Codex tasks load the plugin, automatic stable updates are on, and account/login/preferences remain local. Do not submit a test conversation unless the user requests a test. Refer to `docs/INSTALL.md` for updates and troubleshooting.
