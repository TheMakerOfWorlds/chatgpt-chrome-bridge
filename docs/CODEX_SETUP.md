# ChatGPT Chrome Bridge setup guidance

These instructions apply when a user asks Codex to install or set up this bridge. For maintenance, preserve existing account and project preferences unless the user requests a change.

## Guide the user from the repository link

Treat a request to set up this linked repository as a guided installation. Explain briefly that this is a local macOS bridge using their own ChatGPT session. Do the ordinary download, prerequisite checks and installation steps yourself; do not ask the user to interpret commands or edit configuration. Read this guide before starting. Use a suitable directory on their Mac, reuse an existing checkout when appropriate, and never overwrite unrelated files. If you have only a web reader and no tools on their Mac, say so and direct them to open the link in a local Codex task.

- Check macOS and the Chrome application, then discover `node`, `npm` and `codex` using the normal PATH plus `/opt/homebrew/bin` and `/usr/local/bin`. Reuse compatible installations. If a prerequisite is missing, help install it through the user's existing package manager or the official installer; do not add a second package manager just for this bridge. Pause only for required user interaction such as an OS installer or sign-in.
- Before the plugin is installed, you can list local Chrome profiles from the repository with:

  ```sh
  node --input-type=module -e 'import {listChromeProfiles} from "./scripts/lib/config.mjs"; console.log(JSON.stringify(await listChromeProfiles(), null, 2));'
  ```

- Ask the necessary account and destination questions together when practical: **Which ChatGPT account has your paid plan/Pro access?** and **No project, or a project URL from that account?** Use answers already given. Explain that the ChatGPT account may differ from the Chrome profile's label. Ask for the corresponding local profile when ambiguous.
- Run the installer with those choices. Use a terminal session when input is needed and relay its login prompt to the user in the conversation. Resume the same session after sign-in. If installation already succeeded but login needs attention, use the printed maintenance command's `login` operation instead of reinstalling.
- Finish by reporting the selected local profile, whether Pro was discovered, the saved project/no-project preference, and automatic-update status. Tell them to start a new Codex task to load the tools. If the current task does not see the newly installed tools yet, use the maintenance command for verification; do not say installation failed merely because it needs a new task.

## Setup requirements

1. Read `docs/INSTALL.md`. Check macOS, Chrome, Node.js 20+, and the Codex CLI. Help install missing prerequisites using the user's normal package manager when authorized.
2. Use only the installer's own Chrome profile and ChatGPT account. Never copy login state or configuration from the maintainer or another machine. Ask which of their ChatGPT accounts has their paid plan and Pro access, unless they have already identified it, then select the corresponding local Chrome profile. Even a single Chrome profile may contain the wrong ChatGPT account. The Chrome profile name is not proof of the ChatGPT account signed in inside it; let the user choose/sign in to the intended ChatGPT account.
3. During first setup, explicitly ask: **“Where should new ChatGPT chats go: no project (ordinary chats), or a project in your ChatGPT account?”** Offer **No project (recommended default)** and **Choose a project**. If they choose a project, ask them to open that project in their own ChatGPT account and paste its URL. Do not infer a destination from this repository, the active Codex project, the maintainer's account, or the user's folder name. If the user already provided their choice in this conversation, use it without asking again. Wait for the choice before changing the preference; missing input is not a choice.
4. Run `sh install.sh --no-project` for no project, or `sh install.sh --project-url 'https://chatgpt.com/g/g-p-.../project'` with the supplied URL. Pass `--profile` when the user has selected a local Chrome profile. Use structured command arguments or proper shell quoting for user-supplied values. For a Codex-controlled shell, allocate a terminal if the installer needs interactive input. Do not claim the user can answer a terminal prompt that only Codex controls; relay necessary prompts through the conversation.
5. Let the user complete ChatGPT login/MFA themselves in the dedicated visible Chrome window when needed. They should quit that dedicated Chrome instance with Command-Q before login verification. Do not collect passwords or copy cookies manually. A noninteractive authentication failure needs the documented login flow, not repeated installation.
6. Check the live options returned by setup or `sync_chatgpt_options`. Report whether Pro was found. Authentication alone is not proof of Pro access, and a plan name is not proof of current option availability. If Pro is absent, ask the user to choose their paid-plan account or explicitly continue with the available options. Never silently pass `--allow-no-pro`; use it only for that explicit choice. Do not buy or upgrade a plan as part of setup. The bridge checks UI options, not billing entitlements.
7. The installed maintenance command supports `project --no-project` or `project --project-url URL`; use it to finish the choice if installation completed earlier or the current Codex task has not loaded the plugin tools yet. Once loaded, `configure_chatgpt_bridge(project_url: "")` clears the project and a URL sets it. Read back the saved preference (maintenance `doctor` or bridge status) and report the user's selected destination. A valid URL alone does not prove account access to that project.
8. Explain that new Codex tasks load the plugin, automatic stable updates are on, and account/login/preferences remain local. Do not submit a test conversation unless the user requests a test. Refer to `docs/INSTALL.md` for updates and troubleshooting.
